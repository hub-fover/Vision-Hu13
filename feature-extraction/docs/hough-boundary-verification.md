# 场景07：缺口与粗量化的教学边界

2026-10-06 备用JavaScript环境直接运行当前 `runGeometric`，480×300、种子42、30个噪声点、180个角度格，直线/圆、累加器步长1/2/8、缺口0/0.8共12组。该环境不等同真实浏览器；本轮1909错误仍阻止新的浏览器操作。

直线无噪声真值y=0.4x+81，独立计算法向角111.8014°、ρ=75.2066px。80%缺口时仍有12个真直线点和30个噪声点：

- 1px格最高峰112°、ρ74px、9票，角度误差低于1°。
- 2px格最高峰112°、ρ73px、13票。
- 8px格最高峰116°、ρ41px、14票，角度误差超过3°。

这组真实算法输出构成可解释的粗分辨率失效案例：最高票数从9升到14，模型却偏离真值，说明票数不是准确率。原因包括剩余点段较短、噪声和量化合并，不仅是格宽单一因素；不宣称所有粗格都会失败。

圆真值中心(240,150)、半径70。步长1/2在0和80%缺口下均检出该中心，步长8返回(240,152)，反映量化误差。这里圆梯度是显式教学径向梯度，不冒称从实拍图估计。

另实际断言梯度约束每点2个候选、全方向每点72个候选；默认78个边缘点时分别156与5616次候选投票，约束模式中心仍为(240,150)。候选生成次数不是非零累加器格数，不推论为36倍运行加速。

仍需页面操作的峰值点击、图例与失效提示审查；数值复核不替代交互验收。

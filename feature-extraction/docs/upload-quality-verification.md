# 上传图片切换计算质量

## 问题与修复

旧实现遇到已上传图像时，只显示“请重新选择”，保持旧采样数组。用户随后调参又会用旧分辨率计算，质量控件与计算输入不一致。

新增Chrome测试先确认切换到1280后进入error，再修复质量事件：保留浏览器文件选择器中的本地文件，按本次选定最长边重新解码；终止旧Worker、使用任务编号丢弃过期解码结果。两张上传图同时重新采样。分析坐标系改变时清除手工编辑点与视图偏移，避免把旧像素坐标用于新分辨率。无需再次选图，不进行外部请求。

## 已实际验证

- 场景01：1600×900本地图片，640×360→1280×720→640×360往返。
- 高质量JSON实际尺寸1280×720，原图到分析图缩放0.8，像素中心偏移−0.1（浮点表示存在舍入）。
- 场景09：独立双图都更新为1280×720，原始尺寸仍为1600×900，两个映射均为0.8。
- 在同一浏览器事件轮次开始重新解码后立即复位，最后恢复默认640和实拍双帧，两个文件选择器为空；旧解码结果未重新覆盖复位。
- 单图切换测试记录的外部请求为空。

上述定向测试均在真实Chrome通过。完整回归结果以 `latest-regression.md` 为准；不推论为所有设备的内存或性能验收。

# 画布留白与交互坐标

原有点击换算将整个 CSS 画布矩形直接映射到图像，但 `object-fit: contain` 会在图像与容器比例不一致时添加上下或左右留白。因此真实照片上的窗口位置、SIFT 关键点选择、采样线和控制点拖动可能偏位。

现在先从画布内容尺寸扣除 contain 留白，再反算图像空间的同步缩放、平移；画布边框不计入内容矩形。采样线与其他场景统一使用同一换算。

数值验证包含 200×100 图像放入 100×100 容器时的上下边界，100×200 图像的左右边界，以及两倍缩放、非零平移。五个独立手算坐标断言已通过。对应自动测试为 `tests/canvas-coordinates.test.mjs`。

真实浏览器点击、绘制、拖动回归尚待执行环境恢复。不能用这些数值断言宣称完整交互已通过。

后续复验：完整 `npm test` 已实际运行，56 项通过、0 失败、0 跳过，包含既有 Chrome 点击、拖动及 Snake 自由绘制回归。此回归证明现有交互未出现已覆盖的回归，但尚未增加真实照片留白边界点击的专门浏览器断言，不能据此扩大为所有坐标情形均已验收。

已补充专项浏览器测试 `real photo sampling excludes CSS letterboxing on desktop and mobile`：加载真实山景，以图像中的 y=36 位置分别在 1440×960 和 390×844 视口点击，检查采样参数及真实结果提示为 y=36。旧版按外框换算会把留白计入，因而此断言可捕获偏位。该新增测试尚未执行：命令环境再次报告 1909；切换命令解释器也失败，备用 Node 环境不能直接加载依赖全局 process 的启动模块。最近一次完整 56 项通过不包含此新增测试。
